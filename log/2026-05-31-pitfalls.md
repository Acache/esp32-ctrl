## 坑1: 模拟器 (v9) 和硬件 (v8) LVGL 版本不一致

**现象**: 模拟器里效果完美，烧录后图片乱码、颜色全错、功能不工作。

**根因**: 模拟器用 LVGL v9（SDL 后端），硬件 Arduino 库默认 LVGL v8.4.0。两个大版本 API 完全不同：
- v8: `lv_img_create`, `lv_obj_add_flag`, `lv_obj_align(obj, ALIGN, x, y)`
- v9: `lv_image_create`, `lv_obj_add_flag`, `lv_obj_align(obj, NULL, ALIGN, x, y)`
- 图片描述符结构体字段名/顺序也不同

**解决方案**: 
- ~~不要尝试统一版本，而是为两个环境分别维护代码~~ ❌ 过时方案
- ✅ **新方案：用 `#ifdef LV_USE_SDL` 条件编译 + API 宏兼容层，统一到一个 `ui_pages.h` 文件**
- 模拟器用 `ui_pages.h`（条件编译走 v9 API），硬件 .ino 同样 include `ui_pages.h`（条件编译走 v8 API）
- 再也不能搞两套代码 >:|

## 坑2: LV_COLOR_DEPTH=16 和 LV_COLOR_16_SWAP=1

**现象**: 图像颜色完全错误（蓝绿色调、R/B 通道颠倒）。

**根因**: 
- 硬件 `lv_conf.h` 设置 `LV_COLOR_DEPTH 16` 和 `LV_COLOR_16_SWAP 1`
- SWAP=1 时 `lv_color16_t` 的位布局是 `{green_h:3, red:5, blue:5, green_l:3}`
- RGB565 像素编码公式: `green_h | (red << 3) | (blue << 8) | (green_l << 13)`
- 不可用常规公式 `r5 | (g6 << 5) | (b5 << 11)`

**解决方案**:
```python
g6 = (g >> 2) & 0x3F
r5 = (r >> 3) & 0x1F
b5 = (b >> 3) & 0x1F
green_h = (g6 >> 3) & 7
green_l = g6 & 7
pixel = green_h | (r5 << 3) | (b5 << 8) | (green_l << 13)
```

## 坑3: 图片字节序错误

**现象**: 图片被"切半"重叠显示，类似色块错位。

**根因**: 把 32-bit ARGB 数据发给期望 16-bit RGB565 的硬件。每像素 4 字节被当 2 字节读，数据量翻倍导致错位。

**解决方案**: 硬件必须用 RGB565（2 字节/像素）格式。

## 坑4: 图片背景抠图不彻底

**现象**: 爱因斯坦头像周围有白色/红色方框。

**根因**: 
- 简单阈值 `r<15 and g<15 and b<15` 不够，有些边缘像素比纯黑亮  
- 需要把纯黑背景替换为屏幕背景色 `(13,13,26)` 再编码

**解决方案**: 预处理时用 `r<20 and g<20 and b<20` 或更宽松阈值，把黑色背景完全替换。

## 坑5: 错误结论 — lv_tick_inc 在 Arduino v8 中"不可用"

**实际上这个坑的结论是错的！以下是正确信息：**

**现象**: `'lv_tick_inc' was not declared in this scope`

**真正的原因**: `lv_conf.h` 设置了 `LV_TICK_CUSTOM=1`，条件编译把 `lv_tick_inc` 的声明排除了。不是函数不存在，而是配置让这个函数不可见。

**正确配置**:
- `lv_conf.h` 中 `LV_TICK_CUSTOM = 0`（不要开 1！）
- `bsp_lvgl_port.cpp` 中 `lv_tick_inc(LVGL_TICK_PERIOD_MS)` 正常调用
- `LV_TICK_CUSTOM=1` 在 Arduino LVGL v8.4 上会导致 LV_EVENT_CLICKED 不触发、动画不运行
- 官方示例就是用 `LV_TICK_CUSTOM=0` + `lv_tick_inc()` 方式工作的

## 坑6: 图片描述符的字段初始化顺序

**现象**: C++ designated initializer 顺序错误编译失败

**根因**: LVGL v8 的 `lv_img_dsc_t` 字段顺序为 `header, data_size, data`，指定初始化必须严格按此顺序。

**解决方案**: 用 `einstein_img_init()` 函数运行时逐个字段赋值。

---

## 坑7: SRAM 溢出

**现象**: `region 'sram_seg' overflowed by 667904 bytes`

**根因**: 模拟器的 `lv_conf.h` 中 `LV_MEM_SIZE = (48U * 1024U * 1024U) = 48MB`，远超 ESP32-C6 的 512KB。

**解决方案**: 减小为 `LV_MEM_SIZE = (32U * 1024U)`，同时关闭不需要的功能（ThorVG, Lottie, demos, examples）。

## 🆕 坑8: 模拟器和硬件代码不同步（最严重的坑）

**现象**: 模拟器里单击缩放和双击笑话完美运行，烧录到硬件却没有任何交互反馈。

**根因**: 项目有两套 UI 源码——`ui_pages.h`（模拟器用 v9 API）+ `desk-mate-app.ino`（硬件用 v8 API）。交互逻辑只写在了前者，硬件代码里只有双击笑话没有单击缩放。

**解决方案**: 
- **「模拟器 = 硬件」原则** — UI 源码必须唯一
- 用 `#ifdef LV_USE_SDL` 宏区分模拟器/硬件环境
- 定义 API 兼容宏层（`IMG_CREATE`, `IMG_SET_SCALE`, `TXT_GET_SIZE` 等）
- `.ino` 只包含硬件初始化，UI 全部通过 `#include "ui_pages.h"` 引入
- 再有任何 UI 改动，先在模拟器验证→自动等于硬件效果

**核心教训: 同一份代码，同一份效果。不允许有两套 UI 实现。**
