# 2026-06-01 事后分析：触摸不工作的根因

## 问题回顾
花了整整一天时间才让"单击缩放+双击笑话"在硬件上正常工作。
而这个问题最讽刺的是：模拟器从一开始就是好的，硬件复制了同样的代码却不能工作。

## 根因链

### 第一层：代码有两套
一开始 `ui_pages.h`（模拟器用）和 `desk-mate-app.ino`（硬件用）各自维护了一份UI代码。
硬件代码里只写了双击笑话，没有写单击缩放——直接少了一半功能。

### 第二层：lv_conf.h 不一致（这个是致命伤）
即使把代码统一了，硬件上还是不行。最终发现：
- **我们的 `lv_conf.h`** 设置了 `LV_TICK_CUSTOM=1`，让 LVGL 自动用 `millis()` 获取 tick
- **官方示例的 `lv_conf.h`** 设置了 `LV_TICK_CUSTOM=0`，用手动 `lv_tick_inc()` 喂 tick
- 我们还在 `bsp_lvgl_port.cpp` 中把 `lv_tick_inc` 注释掉了，标为"not available"

**结果：LVGL 的 tick 时钟没跑！**
- 所有定时器不工作 → `LV_EVENT_CLICKED` 不会被触发
- 所有动画不工作 → 笑话的渐隐效果消失
- 但 LVGL 的基本渲染还能跑 → 图片正常显示产生了"系统在正常工作"的错觉

### 第三层：我踩坑日志里记录了错误的结论
踩坑日志第5条写着：
> "坑5: lv_tick_inc 在 Arduino v8 中不可用"
> 解决方案: 直接注释掉 lv_tick_inc 调用（BSP 中有其他 tick 机制）

这个结论是错的。`LV_TICK_CUSTOM=1` 的设置来自模拟器的 `lv_conf.h`，被错误地复制到了硬件配置中。
实际上 `lv_tick_inc` 是存在的，而且官方示例就是靠它的。

### 第四层：调试方法错误
- 发现触摸不工作后，我怀疑事件绑定方式不对 → 改 `LV_EVENT_CLICKED` 为 `LV_EVENT_ALL`→ 雪上加霜
- 怀疑 scrollable 容器 → 清除了 `LV_OBJ_FLAG_SCROLLABLE`→ 没解决
- 怀疑图片尺寸 → 反复改 320/280→ 浪费大量时间
- 始终没有**对比 lv_conf.h** → 这个最简单的事最后才发现

## 教训总结

### 1. 当模拟器工作、硬件不工作时
**不要怀疑 UI 逻辑！** 先在硬件上跑最小可验证程序（如官方 demo），确认基础功能正常。
然后**全量 diff 所有配置文件**，特别是 `lv_conf.h`。

### 2. lv_conf.h 是 LVGL 的灵魂
这个文件控制 LVGL 的全部行为：tick 来源、内存大小、功能开关、字体、动画。
模拟器和硬件的 lv_conf.h 必须保持一致，否则同样的代码行为完全不同。
**核心配置必须版本控制 + 加注释说明为什么这样设。**

### 3. 不要随便注释"不可用"的代码
`lv_tick_inc` 在编译时报过一个错，我就粗暴注释掉了，还写了错误结论到踩坑日志。
正确做法：查文档/官方示例确认正确的用法，而不是自己猜一个"替代方案"。

### 4. 调试不要用 hack 代替系统排查
- 不能用 `LV_EVENT_ALL` 代替 `LV_EVENT_CLICKED`
- 不能用 `lv_timer_create` 代替动画渐隐
- 每个改动要明确知道"我在改什么、为什么这样改"

### 5. 最小化复现
当我发现最简测试（一个按钮+点击计数）也不工作时，就应该立刻怀疑基础配置而非 UI 代码。
但我在那之后又浪费了时间怀疑事件绑定。

## 修复措施
1. `lv_conf.h` 完全采用官方示例的配置，只启用需要的字体
2. `bsp_lvgl_port.cpp` 恢复 `lv_tick_inc()` 调用
3. `LV_TICK_CUSTOM = 0`（和官方一致）
4. 硬件和模拟器的笑话显示都使用动画渐隐（v8/v9 API 条件编译）
5. 踩坑日志删除错误结论，更新为正确信息
