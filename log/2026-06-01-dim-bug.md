# 2026-06-01 教训：Lcd_SetBacklight 在 setup() 中导致白屏

## 现象
实现"30s 无操作降亮"功能时，在 setup() 里加了 `Lcd_SetBacklight(100)`，结果整屏白屏无反应。
**不是 30s 后变白，是启动后立即白屏。**

## 嫌疑代码
```c
void setup() {
  // ... 现有初始化
  bsp_lvgl_init(I2cMasterBus_);     // QSPI 屏幕初始化
  Lcd_SetBacklight(100);             // ❌ 在 bsp_lvgl_init 后立即调
  if (bsp_lvgl_lock(0)) {
    ui_build_all(lv_scr_act());
    bsp_lvgl_unlock();
  }
}
```

## 根因（未完全确认）
- `bsp_lvgl_init` 内部做 QSPI DMA 传输，可能还没完成
- `Lcd_SetBacklight` 通过 I2C 发命令到 AXP2101，**与 QSPI 共享 GPIO 总线可能性高**
- 在 QSPI 还没完成初始化时调 I2C 干扰了屏幕时序 → 屏幕锁在白屏状态

## 白天踩过的相似坑
> ESP32-C6 上 `I2cMasterBus` 和 `Wire` 库不能混用（共享 GPIO 无互斥会白屏）
> — 2026-06-01-analysis.md

**同源问题**：I2C 操作与其他总线/外设初始化冲突时，屏幕会锁死。

## 修复
完全回退亮度功能：
- 删除 `Lcd_SetBacklight(100)` setup 调用
- 删除 `ui_dim_if_idle()` 函数
- 删除 `ui_last_active_ms` 跟踪
- 删除 loop() 里的 1s 轮询

**保留**：电池 10s 轮询（PMU_GetBatteryPercent 仍然在工作）

## 下次正确做法（如果还要做降亮）
- ✅ 在 `bsp_lvgl_init` 完成**并**至少一次 `lv_timer_handler()` 之后，才调 `Lcd_SetBacklight`
- 或者延迟到 `loop()` 里第一次进 idle 时再调
- 或者用 `xTaskCreatePinnedToCore` 单独任务，在 setup 之后 500ms 再调

## 字节影响
- 加亮度功能：+212 bytes flash
- 回退后：+0（恢复电池版大小 738,524 bytes）
